# Калькулятор выражений с отменой (Вариант 8)

## Описание задания

Консольное приложение на C# (.NET 6+), реализующее калькулятор арифметических выражений со скобками.

**Что должно работать в демо:**
- Ввод арифметического выражения (например, `((2+3)*4-5)`)
- Вывод результата вычисления
- Показ дерева выражения
- Отмена последней операции

## Использованные паттерны проектирования

### 1. Компоновщик (Composite)

**Проблема:** Выражение состоит из чисел и операций, вложенных друг в друга произвольным образом (`((2+3)*4-5)`). Нужно работать с ними единообразно — и с отдельным числом, и с составным выражением.

**Решение:** Интерфейс `IExpression` реализуется как листьями (`NumberExpression`), так и узлами (`BinaryExpression`). Это позволяет строить дерево выражений любой глубины и обрабатывать его рекурсивно, не различая типы узлов.

**Без паттерна:** Пришлось бы использовать множество `if/switch` для проверки типа каждого элемента, что сделало бы код хрупким и трудным для расширения новыми операциями.

---

### 2. Интерпретатор (Interpreter)

**Проблема:** После разбора выражения в дерево нужно вычислить его значение. Логика вычисления разная для чисел и операций, но должна быть инкапсулирована внутри узлов.

**Решение:** Каждый узел знает, как вычислить своё значение через метод `Interpret()`. Листья возвращают число, узлы рекурсивно вызывают `Interpret()` у дочерних узлов и применяют свою операцию (`+`, `-`, `*`, `/`).

**Без паттерна:** Вычисление пришлось бы делать в одном большом методе с обходом дерева и проверкой типов, что нарушало бы принцип единой ответственности.

---

### 3. Команда (Command)

**Проблема:** Пользователь должен иметь возможность отменить последнюю операцию и вернуть калькулятор в предыдущее состояние.

**Решение:** Каждая операция инкапсулируется в объект `CalcCommand` с методами `Execute()` и `Undo()`. До выполнения сохраняется снимок состояния (`CalculatorState`) в поле `_backup`. Метод `Undo()` восстанавливает это состояние. История команд хранится в стеке `Stack<ICommand>`.

**Без паттерна:** Пришлось бы вручную хранить историю состояний в `Program.cs`, что привязало бы логику отмены к конкретному интерфейсу и сделало код запутанным.
